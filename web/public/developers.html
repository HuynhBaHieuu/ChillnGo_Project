ChillnGo API

The ChillnGo API is a public JSON REST API for ChillnGo, a Vietnamese travel social network of real multi-day trip journeys — day by day, stop by stop, with what each stop actually cost. Read published journeys, check-ins, livestreams and profiles without an account; sign in to create journeys and clone itineraries.

Base URL: https://chillgo-project-web.vercel.app/api

Quickstart

Public data needs no account and no key. Try it:

# Published journeys, newest first
curl https://chillgo-project-web.vercel.app/api/posts

# One journey, day by day and stop by stop
curl https://chillgo-project-web.vercel.app/api/posts/{id}

# What the API offers, and where its docs are
curl https://chillgo-project-web.vercel.app/api

Or with the CLI:

npx chillngo posts
npx chillngo post {id}

Authentication

There are no separate API keys. Reading public data needs no credentials. To act as a user, sign in with the account's email and password, then send the returned token as a bearer token: 

curl -X POST https://chillgo-project-web.vercel.app/api/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"email":"you@example.com","password":"…"}'
# → { "token": "…", "user": { … } }

curl https://chillgo-project-web.vercel.app/api/auth/me \
  -H 'Authorization: Bearer <token>'

Create an account at /register. Tokens expire; sign in again when a request answers 401 UNAUTHORIZED.

Public endpoints

EndpointWhat it returns
GET /api/postsPublished journeys, newest first. ?author=<userId> narrows to one author.
GET /api/posts/{id}One journey: days, stops with coordinates, notes and estimated cost.
GET /api/posts/{id}/commentsA journey's comments.
GET /api/checkinsRecent check-ins. ?authors=a,b and ?before=<ISO time>.
GET /api/livestreamsStreams live now. /replays lists recorded streams; /history?host=<userId> one host's past streams.
GET /api/users/{id}A public profile.
GET /api/settings/publicWhether sign-up is open, and the site announcement.

Signed-in endpoints cover writing journeys, comments and likes, cloning itineraries, AI-assisted drafts, check-ins, livestreaming and notifications. The OpenAPI description lists all of them.

Errors

Every error is JSON with the same fields:

{
  "message": "Không tìm thấy",
  "code": "NOT_FOUND",
  "status": 404,
  "hint": "No such resource or route. Check the path and id against the OpenAPI description.",
  "docs": "/api/openapi.json"
}

message is Vietnamese text for people. code is a stable identifier (NOT_FOUND, VALIDATION_FAILED, UNAUTHORIZED, RATE_LIMITED, …). hint says what to do next. Validation errors add issues, one entry per field.

Rate limits

Sign-in and write routes are rate-limited per account or IP address. A limited request gets 429 RATE_LIMITED with RateLimit and RateLimit-Policy headers (IETF draft 8); wait as they say, then retry.

Sandbox

There is no separate sandbox environment. The public read endpoints are safe to call against production. Use a test account for anything that writes, and run the server locally (server/ on GitHub) to experiment freely.
